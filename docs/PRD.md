# ZhiYu 产品需求文档 (PRD)

> 本文档定义 ZhiYu 的产品需求、功能范围、用户故事和非功能需求。从 [设计规格](superpowers/specs/2026-05-17-zhiyu-backend-design.md) 逆向推导并补充。

## 1. 产品概述

### 1.1 产品愿景

ZhiYu 是一款 AI-native 的应用平台（具体 AI 能力待业务方定义，本文档聚焦用户体系与商业化基础设施），为用户提供从免费游客到付费订阅的完整体验。核心差异化在于灵活的多方式认证体系和安全可靠的订阅管理。

### 1.2 目标用户画像

| 画像 | 特征 | 核心诉求 |
|------|------|---------|
| **免费游客** | 首次体验，低投入决策 | 无门槛注册，快速体验核心功能，理解产品价值 |
| **个人用户 (Lite)** | 日常使用，轻度依赖 | 价格敏感，在意功能/价格比，期望稳定服务 |
| **重度用户 (Pro)** | 工作/创作依赖，高频使用 | 无限制使用、优先响应、完整功能 |
| **后台管理员** | 运营、客服、技术 | 高效查看和管理用户/订单，处理退款和工单 |

### 1.3 核心价值主张

1. **一次注册，多种方式登录**：密码、短信、微信/QQ/Google/Apple、指纹/面容 (WebAuthn)，永不丢失账户
2. **灵活的订阅管理**：免费/试用/付费三级体系，升级折价、降级预约、随时取消
3. **安全与便利兼备**：TOTP 双因素、多设备管理、盗用检测、账户恢复工单

## 3. 用户故事

### 3.1 认证模块

```
US-AUTH-01: 作为新用户，我想用邮箱和密码注册账户，以便开始使用 ZhiYu。
验收标准:
  - 提交用户名、密码、邮箱、CAPTCHA
  - 系统检查唯一性，创建账户，发送欢迎邮件
  - 成功返回 JWT token 直接登录

US-AUTH-02: 作为注册中的用户，我需要先通过邮箱验证码，以证明邮箱所有权。
验收标准:
  - 先完成 CAPTCHA 滑块验证
  - 60 秒内不可重复发送
  - 验证码 5 分钟有效

US-AUTH-03: 作为已登录用户，当 access_token 过期时，系统应自动刷新而不需要我重新登录。
验收标准:
  - access_token 15 分钟有效
  - refresh_token 7 天有效
  - 刷新后旧 token 对立即失效

US-AUTH-04: 作为忘记密码的用户，我可以通过邮箱重置密码。
验收标准:
  - 提交邮箱 → 收到重置链接邮件 → 设置新密码
  - 重置后所有设备强制登出

US-AUTH-06: 作为用户，我想用已有的微信/QQ/Google/Apple 账户直接登录，省去注册步骤。
验收标准:
  - 首次登录自动创建账户
  - 未绑邮箱前 scope=LIMITED，只能访问 /auth/* 和 /user/bind-email
  - 绑定邮箱后 scope 升级为 FULL

US-AUTH-08: 作为用户，我想查看和管理所有已登录的设备，能踢出可疑设备。
验收标准:
  - 最多 5 个设备同时在线
  - 可查看设备名、平台、最后活跃时间
  - 踢出后该设备 token 立即失效

US-AUTH-09: 作为安全敏感的用户，我想启用 TOTP 双因素认证来保护账户。
验收标准:
  - 扫码绑定 Google Authenticator
  - 登录时密码后需输入 6 位 TOTP 码
  - 提供 5 个一次性恢复码

US-AUTH-10: 作为用户，我想用指纹/面容 (WebAuthn) 快速登录。
验收标准:
  - 注册指纹/面容凭证
  - 登录时无需密码，直接生物识别

US-AUTH-11: 作为丢失所有认证方式的用户，我能通过人工审核恢复账户。
验收标准:
  - 提交已知信息（邮箱/手机/用户名）
  - 管理员审核通过后发送恢复链接
  - 7 天内有效
```

### 3.2 订阅模块

```
US-SUB-01: 作为潜在用户，我想查看所有套餐的功能和价格，以便做出购买决定。
验收标准:
  - 无需登录即可查看套餐列表
  - 显示功能、配额、价格

US-SUB-03: 作为用户，我想用微信/支付宝购买 Lite 或 Pro 套餐。
验收标准:
  - 选择套餐和周期（月/年）
  - 调起微信/支付宝支付
  - 支付成功后自动激活订阅

US-SUB-04: 作为 Lite 用户，我想升级到 Pro，剩余天数的价值应折价计算。
验收标准:
  - 升级立即生效
  - 新价格 - 未用天数价值 = 支付金额
  - 降级预约，当前周期结束后生效

US-SUB-06: 作为误购用户，我可以在规定条件下申请退款。
验收标准:
  - 选择退款原因
  - 管理员审核
  - 退款后订阅降级为游客
  - 同周期内不可重复购买（防刷）
```

### 3.3 管理后台

```
US-ADMIN-01: 作为管理员，我通过后台独立账户登录管理系统。
验收标准:
  - 用户名+密码 → TOTP（如已启用） → DJWT
  - 30 分钟无操作自动超时退出
  - 支持密码/短信/微信/企微扫码多种方式

US-ADMIN-02: 作为管理员，我可以查看、搜索、禁用用户。
验收标准:
  - 列表支持分页、状态筛选、关键词搜索
  - 详情显示用户信息+认证身份+订阅状态+设备列表
  - 禁用/启用操作需填写原因

US-ADMIN-04: 作为系统管理员，不同角色应看到不同的菜单和操作权限。
验收标准:
  - SUPER_ADMIN 全部权限
  - ADMIN 不可管理后台用户和系统配置
  - CS 仅可查看用户和订阅
```

## 4. 非功能需求

### 4.1 性能

| 指标 | 目标值 | 测量方法 |
|------|--------|---------|
| API P50 延迟 | < 100ms | Prometheus histogram |
| API P99 延迟 | < 500ms | Prometheus histogram |
| 登录接口 P99 | < 1000ms（含第三方OAuth回调） | — |
| 支付回调处理 P99 | < 2000ms | — |
| 并发用户数 | 10,000 并发（初期） | JMeter 压测 |
| 数据库连接池利用率 | < 80% | HikariCP metrics |

### 4.2 可用性

| 指标 | 目标 |
|------|------|
| 核心 API 可用性 | 99.9%（月维度，排除计划维护） |
| 计划维护窗口 | 每月第二个周日 03:00-05:00 |
| RTO（恢复时间目标） | < 30 分钟 |
| RPO（恢复点目标） | < 5 分钟（数据库） |

### 4.3 安全

- OWASP Top 10 防护全覆盖
- 密码 BCrypt cost factor ≥ 12
- JWT RS256 非对称签名
- 所有外部输入必须校验（`@Valid`）
- 支付回调签名验证
- HTTPS 强制，HSTS `max-age=31536000`
- 敏感数据日志脱敏

### 4.4 可维护性

- 代码覆盖率 ≥ 80%
- 所有 API 具备 OpenAPI 文档
- 审计日志覆盖所有管理员操作
- 模块间低耦合，按领域隔离

## 5. MVP 范围边界

### 第一版包含

- 邮箱注册/登录 + CAPTCHA
- JWT Token 管理（签发、刷新、退出）
- 密码重置
- 免费游客套餐（永久）
- 套餐列表查看
- 用户个人信息管理
- 账户注销（软删除，30 天）
- 管理后台：密码登录 + TOTP、用户管理、审计日志

### 第一版不包含

- 第三方登录（微信/QQ/Google/Apple）
- 短信登录
- WebAuthn
- 付费套餐购买（微信支付/支付宝）
- Apple/Google IAP
- 账户恢复工单
- 通知模板管理
- 系统配置可视化管理
- 日志检索管理后台

## 6. 术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| 游客 | Guest / Free User | 免费套餐用户，可使用基础功能 |
| 用户 | User | 注册后的 ZhiYu 平台用户 |
| 管理员 | Admin | 管理后台用户，独立于普通用户表 |
| 套餐 | Plan | 功能+配额的打包定义（free / lite / pro） |
| 订阅 | Subscription | 用户与套餐的关联关系 |
| 订单 | Order | 一次购买行为产生的支付订单 |
| 配额 | Quota | 用户在一定周期内可使用资源的限制 |
| 认证方式 | Auth Identity | 用户绑定的一种登录凭证（密码/微信/手机等） |
| 设备 | Device | 用户登录的客户端设备，每设备独立 session |
| Scope | Scope | JWT 中的权限范围（LIMITED / FULL） |
| JTI | JWT ID | JWT 唯一标识符，用于黑名单管理 |
| Refresh Token 轮换 | Rotation | 每次使用 refresh_token 时发放新对并废弃旧 token |
| CAPTCHA | CAPTCHA | 人机验证（阿里云滑块） |
| TOTP | Time-based OTP | 基于时间的一次性密码（Google Authenticator） |
| WebAuthn | WebAuthn/FIDO2 | 基于公钥的无密码认证标准 |
| 幂等 | Idempotency | 同一请求多次执行结果相同（支付回调去重） |

## 7. 竞品分析

### 7.1 直接竞品

| 产品 | 优势 | 劣势 | ZhiYu 差异化 |
|------|------|------|-------------|
| ChatGPT (OpenAI) | 品牌认知度最高、模型能力强 | 国内访问受限、无微信生态集成、定价美元 | 国内可直接访问、微信/QQ 一键登录、人民币定价 |
| 文心一言 (百度) | 百度生态、中文理解好 | 插件生态弱、B端定制少 | 灵活的套餐体系、开放 API、多平台客户端 |
| 通义千问 (阿里) | 阿里云生态、企业级支持 | 定价偏高、C端体验一般 | 免费套餐可用、渐进式付费、更好的移动端体验 |
| Kimi (月之暗面) | 超长上下文、文件处理强 | 生态单薄、无管理后台 | 完善的 Admin 后台、RBAC 权限、对账系统 |
| DeepSeek | 开源模型、成本低 | 商业化不成熟、缺乏企业功能 | 完整商业闭环（支付/退款/发票）、合规体系 |

### 7.2 间接竞品

| 领域 | 代表产品 | ZhiYu 定位 |
|------|---------|-----------|
| AI 写作助手 | Jasper, Copy.ai, 秘塔写作猫 | 更广泛的使用场景（不仅限写作） |
| AI 编程助手 | GitHub Copilot, Cursor | 不直接竞争，但可能成为集成目标 |
| AI 图像生成 | Midjourney, 即梦 | 可作为下游能力集成 |

### 7.3 核心竞争力总结

1. **国内合规优先**: PIPL 合规、ICP 备案就绪、数据不出境
2. **全平台覆盖**: iOS + Android + Web Admin，统一账户体系
3. **灵活商业化**: 免费入门 → 试用转化 → 付费留存，完整漏斗
4. **安全认证体系**: 多因素认证、设备管理、Token 盗用检测
5. **开放集成**: 微信/QQ/Google/Apple 登录 + 微信/支付宝/Apple/Google 支付
